# Mailman + Postfix on `mci`

This document describes how mailing-list mail is configured on `mci`, split into
what the Nix configuration does on the system and what must be configured
**outside** of Nix (Cloudflare DNS and operational checks).

Both directions are enabled: **outbound** (signup/confirmation/list traffic
leaving the box) and **inbound** (mail addressed *to* list addresses, which is
what makes discussion lists work).

## Architecture

```
Outbound:
  GNU Mailman ─SMTP─> Postfix (smtpd) ─rspamd milter (DKIM sign)─> Postfix (smtp) ─> Internet
                                                                         │
                                                              egress bound to the
                                                              dedicated mail IPs

Inbound:
  Internet ─SMTP :25 (STARTTLS)─> Postfix (smtpd) ─relay_domains+transport─> Mailman (LMTP :8024)

Web:
  nginx [::1]:18477 <─ Caddy reverse_proxy (lists.as63477.net)
```

- Mail host: `mx.mci.as63477.net`
- Sending IPs (bound on `lo`, announced via BGP from this machine's own
  `155.103.251.0/24` and `2602:f542:bee::/48`):
  - IPv4 `155.103.251.25`
  - IPv6 `2602:f542:bee::25`
- List/auth domain: `lists.as63477.net`
- Site owner: `postmaster@as63477.net`

All mail-related Nix configuration lives in
[`mail.nix`](./mail.nix). Network interfaces, BGP, firewall and the authoritative
reverse-DNS zones live in [`default.nix`](./default.nix), [`routing/`](./routing)
and [`dns/`](./dns).

## On-system configuration (managed by Nix)

### Postfix (`services.postfix.settings.main`)

| Setting | Value | Why |
| --- | --- | --- |
| `myhostname` | `mx.mci.as63477.net` | HELO/EHLO and `Received:` identity. Must be an FQDN whose forward (A/AAAA) and reverse (PTR) records agree, or strict receivers reject the connection. |
| `myorigin` | `lists.as63477.net` | Domain appended to locally-generated mail (cron/root/bounces) so it lands under an SPF-covered domain. |
| `smtp_bind_address` | `155.103.251.25` | Force IPv4 egress from the dedicated mail IP (matches PTR/SPF). |
| `smtp_bind_address6` | `2602:f542:bee::25` | Same for IPv6. |
| `smtp_bind_address_enforce` | `yes` | Defer delivery rather than silently egress from the wrong source address. |
| `smtp_address_preference` | `any` | Let Postfix fall back to IPv4 when a remote's IPv6 `:25` is unreachable. (Was `ipv6`, which had no fallback and could hard-fail delivery.) |
| `milter_default_action` | `accept` | If the rspamd milter is down, accept (unsigned) rather than defer all mail. |
| `smtpd_tls_chain_files` | `/var/lib/acme/mx.mci.as63477.net/full.pem` | Inbound STARTTLS cert+key (ACME `full.pem` = key + full chain). |
| `smtpd_tls_security_level` | `may` | Opportunistic inbound TLS: offer STARTTLS but still accept plaintext, so mail is never bounced for lack of TLS. |
| `transport_maps` / `local_recipient_maps` | `hash:/var/lib/mailman/data/postfix_lmtp` | Generated by Mailman; routes list addresses to Mailman over LMTP (inbound delivery). |
| `relay_domains` | `hash:/var/lib/mailman/data/postfix_domains` | Generated by Mailman; the set of list domains Postfix accepts and relays to Mailman (inbound). |

`inet_interfaces` is left at the Postfix default (`all`), so smtpd listens on the
BGP-announced mail IPs. `mydestination` is left at its default, which does **not**
include `lists.as63477.net`; list mail is handled as a relay domain and forwarded
to Mailman's LMTP, not delivered locally.

The Postfix milter sockets (`smtpd_milters` / `non_smtpd_milters` =
`unix:/run/rspamd/rspamd-milter.sock`) are set automatically by
`services.rspamd.postfix.enable`, not by hand.

### DKIM signing (`services.rspamd`)

opendkim is marked **insecure/unmaintained** in nixpkgs, so DKIM signing is done
with rspamd (the nixpkgs-recommended alternative).

```nix
services.rspamd = {
  enable = true;
  postfix.enable = true;            # creates the milter + wires Postfix
  locals."dkim_signing.conf".text = ''
    selector = "mail";
    path = "/var/lib/rspamd/dkim/$domain.$selector.key";
    sign_local = true;              # Mailman submits over loopback => "local"
    sign_authenticated = true;
    allow_username_mismatch = true;
    use_domain = "header";          # sign with the From: header domain
  '';
};
```

- rspamd runs in self-scan (milter) mode and signs outbound mail using the From
  header domain (`lists.as63477.net`).
- The DKIM keypair is **auto-generated on first start** by an `ExecStartPre`
  hook (`rspamadm dkim_keygen`) if it does not already exist:
  - private key: `/var/lib/rspamd/dkim/lists.as63477.net.mail.key` (stays on the
    host, never committed to this repo)
  - public record: `/var/lib/rspamd/dkim/lists.as63477.net.mail.txt` (the value
    you publish in DNS — see hand-off below)
- Because the milter processes all mail Postfix sends, rspamd also self-scans
  outbound list mail. It is **not** backed by Redis here, so stateful modules
  (bayes, ratelimit, greylisting) are inactive; DKIM signing with a static key
  does not need Redis. If outbound mail is ever tagged/rejected by rspamd,
  revisit its actions/thresholds.

### Inbound delivery & TLS

- Inbound SMTP is allowed via the firewall **input chain**
  (`networking.firewall.extraInputRules` in [`default.nix`](./default.nix)),
  scoped to the mail IPs only, mirroring the DNS rules:

  ```nft
  ip  daddr 155.103.251.25  tcp dport 25 accept
  ip6 daddr 2602:f542:bee::25 tcp dport 25 accept
  tcp dport 25 drop
  ```

  Ports `465` (implicit TLS) and `587` (STARTTLS) are opened the same way (also
  scoped to the mail IP). Ports are intentionally **not** in `allowedTCPPorts` —
  that would open them on every address. Restricting by destination IP keeps
  SMTP off the transit IP (`23.143.82.39`) and every other address.

### Secure submission (ports 465 / 587)

`enableSubmissions` (465, implicit TLS) and `enableSubmission` (587, STARTTLS)
provide TLS-encrypted SMTP endpoints, reusing the same ACME cert as port 25
(`smtpd_tls_chain_files`). Both enforce TLS (`smtpd_tls_security_level =
encrypt`; 465 additionally uses wrappermode).

These are configured **without SASL authentication** (`smtpd_sasl_auth_enable =
no`) to keep things simple. Consequences:

- They do **not** provide authenticated outbound relay — a client cannot log in
  and send mail to arbitrary destinations through them.
- They are **not** an open relay: Postfix's default relay restrictions
  (`permit_mynetworks, permit_sasl_authenticated, defer_unauth_destination`)
  mean only mail for the local/list domains is accepted, same as port 25.

In other words, 465/587 are TLS-wrapped equivalents of the port-25 listener. To
turn them into real authenticated submission (so a mail client can relay
outbound), add a SASL backend (the Postfix module expects Dovecot SASL:
`smtpd_sasl_type = dovecot`, a Dovecot `service auth` unix socket under the
Postfix queue dir, and a passdb), then set `smtpd_sasl_auth_enable = yes` and
`smtpd_client_restrictions = permit_sasl_authenticated,reject` on the submission
services. That is the only "complicated" piece intentionally left out.
- Incoming mail for `lists.as63477.net` matches `relay_domains` (accepted) and is
  routed by `transport_maps` to Mailman's LMTP listener on `127.0.0.1:8024`.
- Inbound STARTTLS uses an ACME certificate for `mx.mci.as63477.net`, issued via
  the **DNS-01** challenge over Cloudflare (`security.acme`, reusing the
  `cfDnsApiToken` secret already declared by the caddy module). DNS-01 needs no
  inbound ports. The cert is group-readable by `postfix` and Postfix is reloaded
  on renewal (`reloadServices`). A preliminary self-signed cert is created on
  first boot, so Postfix starts cleanly before the real cert is issued.

### Mailman + web (`services.mailman`, nginx, Caddy)

- `services.mailman` with `enablePostfix = true` generates the Postfix LMTP
  transport/relay maps referenced above and runs the LMTP runner that receives
  inbound list mail.
- Hyperkitty web UI is served by nginx on `[::1]:18477` and exposed publicly by
  Caddy at `https://lists.as63477.net`.

## External configuration (NOT doable in Nix — action required)

These cannot be expressed in this repo and must be done by hand.

### Cloudflare DNS

1. **SPF — already correct, no change needed.**
   `lists.as63477.net` publishes `v=spf1 include:spf.as63477.net -all`, and
   `spf.as63477.net` authorizes `ip4:155.103.251.0/24` and `ip6:2602:f542::/36`,
   which cover both sending IPs.

2. **DKIM — add.** After the first deploy, read the generated record on the host:

   ```
   cat /var/lib/rspamd/dkim/lists.as63477.net.mail.txt
   ```

   `rspamadm dkim_keygen` emits a ready-to-use record of the form
   `mail._domainkey IN TXT ( "v=DKIM1; k=rsa; p=..." )`. Publish it as a `TXT`
   record at:

   ```
   mail._domainkey.lists.as63477.net
   ```

   (Cloudflare wants the quoted string contents; concatenate the split quoted
   segments into the single value.)

3. **DMARC — add.** Create a `TXT` record at `_dmarc.lists.as63477.net`:

   ```
   v=DMARC1; p=none; rua=mailto:postmaster@as63477.net
   ```

   Start with `p=none` (monitor), tighten to `quarantine`/`reject` only after
   confirming SPF and DKIM pass.

4. **MX — done.** `lists.as63477.net` has an `MX` pointing at
   `mx.mci.as63477.net` (which resolves to the `.25` IPs). This is required for
   inbound list mail.

> Note: `lists.as63477.net` carries `CNAME` (-> `mci.unicycl.ing`), `TXT`, and
> `MX` records at the same name. Co-locating a `CNAME` with other record types
> is not strictly RFC-compliant, but Cloudflare's CNAME flattening serves them
> correctly. If inbound delivery ever misbehaves, the cleanest fix is to drop
> the `CNAME` and set explicit `A`/`AAAA` (`155.103.251.1` / `2602:f542:bee::1`)
> alongside the `MX`/`TXT`.

### Diagnostics to confirm delivery

Run on `mci` (these are read-only checks; they confirm which failure mode is in
play and that signing works after deploy):

```sh
# Effective Postfix settings (verify myhostname, milters, binds)
postconf -n

# Anything stuck, and why (timeouts => egress; rejects => HELO/auth)
postqueue -p
journalctl -u postfix --no-pager -n 300

# Mailman outgoing runner
journalctl -u mailman.service --no-pager -n 300

# rspamd is up and signing (look for the DKIM_SIGNED symbol / DKIM-Signature)
journalctl -u rspamd --no-pager -n 100

# Source-bound egress reachability to a real MX on :25
nc -vz -s 155.103.251.25 gmail-smtp-in.l.google.com 25
nc -vz -s 2602:f542:bee::25 gmail-smtp-in.l.google.com 25

# End-to-end: send a test and read the result headers at the receiver
sendmail -v you@gmail.com
```

At the receiving end (e.g. Gmail "Show original"), confirm
`spf=pass`, `dkim=pass`, and `dmarc=pass` with the domain aligned to
`lists.as63477.net`.

### Verifying inbound

After deploy, confirm inbound delivery end to end:

```sh
# Postfix is listening on :25
ss -ltnp | grep ':25'

# The ACME cert for the mail host exists
ls -l /var/lib/acme/mx.mci.as63477.net/

# Mailman LMTP runner is listening on 127.0.0.1:8024
ss -ltnp | grep 8024

# Watch a real inbound message land and get routed to LMTP
journalctl -u postfix -f        # expect: relay=127.0.0.1[127.0.0.1]:8024 ... status=sent
```

From an external account, send to a list's posting address (e.g.
`<listname>@lists.as63477.net`) or to `<listname>-join@lists.as63477.net` to
subscribe, and confirm it appears in the list / Hyperkitty archive.

## Possible future work

- **Authenticated submission (587/465):** the ports are enabled with TLS but no
  SASL. Adding a Dovecot SASL backend would let mail clients log in and relay
  outbound through this host; not required for list operation.
- **Redis-backed rspamd:** would enable bayes/ratelimit/greylisting if this host
  ever also handles general inbound filtering.
- **relay_recipient_maps:** to reject unknown `@lists.as63477.net` recipients at
  SMTP time (reduces backscatter) instead of accepting then bouncing via LMTP.
